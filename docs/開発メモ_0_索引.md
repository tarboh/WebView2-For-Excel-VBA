## VBA-WebView2 のコンセプト (たーぼーさん明示、2026-08)

**普通のブラウザを完全再現することは目的ではない。**完成度が高いのは良いことだが、
VBA でダラダラと快適にネットサーフィンするのが目的ではない。目指すのは次の 2 点:

1. **Web ページを自動制御することに優れた使いやすさを発揮すること**
2. **ユーザーフォーム上のコントロールを HTML で配置することでモダンな GUI を提供すること**

**この 2 点が、以降の取捨選択の基準になる。**

### R-1. ICoreWebView2 追加インターフェースのメソッド実装

メソッド単位ではなく「何ができるようになるか」単位で選別する。

**高価値 (コンセプト①に直結)**
- ★`CallDevToolsProtocolMethod`★ — 単体で CDP 全域が開く。ネットワーク傍受・DOM 操作・
  Cookie・スクショ・PDF まで届く範囲が異常に広い。**費用対効果が突出**
- `WebResourceRequested` + `AddWebResourceRequestedFilter` — リクエストの傍受・書き換え
- `NavigateWithWebResourceRequest` (ICoreWebView2_2) — POST を自前で組み立てて送る
- `AddScriptToExecuteOnDocumentCreated` — ページ読込前にフックを仕込む。R-4 の土台
- `get_CookieManager` (ICoreWebView2_2) — 認証状態の保存・復元
- `PrintToPdf` (ICoreWebView2_7) — 帳票出力。Excel VBA との相性が良い

**優先度を下げてよい**: Zoom / Fullscreen / AcceleratorKeyPressed / PermissionRequested。
「普通のブラウザらしさ」の話でコンセプトから外れる。`ProcessFailed` だけは堅牢性の観点で例外。

### R-2. WebView2Loader.dll を使わない起動 ★実現可能性は高い★

C 版ラッパーの実装 (たーぼーさん提供の `my_webview2.c`) が示す手順は 4 手で、全部 VBA でできる。

1. `RegOpenKeyExW` (HKLM, `KEY_WOW64_32KEY` 付き) →
   `Software\Microsoft\EdgeUpdate\ClientState\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` の
   `EBWebView` 値を読む
2. 末尾に `\EBWebView\x64\EmbeddedBrowserWebView.dll` を連結
3. `LoadLibraryW` → `GetProcAddress("CreateWebViewEnvironmentWithOptionsInternal")`
4. 得た関数ポインタを既存の `dcf` で呼ぶ
   (`checkRunningInstance=1, runtimeType=0, userDataFolder, options, handler`)

★**最大のメリットは機能ではなく配布形態**★ — `WebView2Loader.dll` の同梱が不要になり、
**xlsm 単体配布**に一歩近づく。「外部ライブラリゼロ」の筋にも合う。

**着手時の注意 (先に記録)**
- ★C 版の `FreeLibrary(module)` は真似してはいけない★ コールバックは非同期で後から来るのに
  DLL をアンロードしている。たまたま Edge 本体が同 DLL を参照していて生きているだけの可能性が高い。
  **VBA 版では FreeLibrary しない** (プロセス終了まで保持)
- `CreateWebViewEnvironmentWithOptionsInternal` は**非公開 API**。Edge の更新で壊れうる →
  **既存の Loader 経由を残してフォールバックにする** (設計原則 75 と同じ発想)
- 現状 `hr = CreateCoreWebView2EnvironmentWithOptions(0, StrPtr(path), 0, pVTableObj)` と
  第 3 引数 (options) に **NULL** を渡しているので、そこは何も変えずに移行できる
  ※**前提訂正 (D-1 時点)**: R-2 を「配布形態が改善する」と評価していたが、これは誤り。
    **WebView2Loader.dll は現行の Excel に最初から同梱されており** (Office アドイン用に
    用意されているものを本プロジェクトが流用している)、ブックに添付する必要は元々ない。
    したがって R-2 で得られるものはほぼ無く、非公開 API に乗り換えることで Edge 更新に

    また R-5 (拡張機能) を「R-2 で環境オプションの足場ができる」として R-2 に紐づけて
    いたが、オプションの vtable を手作りする作業は Loader 経由でも同じなので、
    **R-2 は R-5 の前提ではない**。R-5 は独立して評価すること。

      D-1 時点では無効。本ファイル末尾の「未解決 / 次段の宿題」を正とすること。★

### R-3. TreeView / ListView 相当のフォームコントロール

コンセプト②に直結。**ActiveX が既定で禁止される現代環境では実需がはっきりしている。**

**タブバー自体が既に「WebView2 で作った独自コントロール」なので、最も地続きの拡張。**

### R-4. MSHTML 相当ライブラリ ★Claude 私見では最重要★

コンセプト①の核心。やれば本プロジェクトの性格が変わる規模。

★**D 軸として着手済み。D-1 (同期評価) / D-2 (読み取り) / D-3 (書き込み・操作 + DOM 条件待ち) / D-4 (静穏待ち) まで完了**★ 下記の「難所は同期取得」は D-1 で解決済み。

  JS を組み立てる。これで**エスケープ地獄を「ハンドル + プロパティ」に還元できる**
- ★難所は同期取得★ `ExecuteScript` は非同期なので `el.InnerText` が値を返すには待ちループが
  要る。既存の `WaitPaneReady` の `DoEvents` パターンが土台になるが、
  **仕様事実 14 (デッドロック) と 20 (EBMode) が直撃する領域**。設計に最も時間を割くべき箇所

  `QuerySelectorAll` / `.InnerText` / `.Value` / `.Click` / `.SetAttribute`)

### R-5. 拡張機能 (Authenticator 等)

実需は明確だが技術的な壁が 1 つ。有効化には環境生成時に `ICoreWebView2EnvironmentOptions` の
`AreBrowserExtensionsEnabled` を真にし、その後 `ICoreWebView2Profile7::AddBrowserExtension` を
呼ぶ必要がある。**問題は前者で、環境オプションは「呼ぶ側」ではなく「実装して渡す側」の
COM オブジェクト**。現在 NULL を渡している第 3 引数に、**VBA で vtable を手作りしたオプション
オブジェクトを渡す**必要がある。`ComCallbackHandler` と同じ方向だが実装すべきプロパティ数が
多く、コストは中〜大。

**★R-2 をやると第 3 引数を触る足場ができるので、R-2 → R-5 の順が自然★**
