## このプロジェクトは何か
Excel VBA **だけ** (外部 COM ライブラリ不使用、マシンコードサンク・SAFEARRAY 系
メモリプリミティブ・手作り vtable のみ) で WebView2 ブラウザコントロールを実装する
プロジェクト。開発言語は日本語。**タブブラウザとして一通り使える形は完成済み。
現在は「ページ自動制御 (MSHTML 相当)」の D 軸を進行中で、D-2 まで完了。**

### ★VBA-WebView2 のコンセプト (たーぼーさん明示。取捨選択の基準)★
**普通のブラウザを完全再現することは目的ではない。** 完成度が高いのは良いことだが、
VBA でダラダラと快適にネットサーフィンするのが目的ではない。目指すのは次の 2 点:

1. **Web ページを自動制御することに優れた使いやすさを発揮すること**
2. **ユーザーフォーム上のコントロールを HTML で配置することでモダンな GUI を提供すること**

判断に迷ったら、この 2 点に照らして「本家に合わせる価値があるか」を問うこと。
**D 軸はコンセプト①への直接の投資である。**

## ★特に忘れやすい仕様事実★

### 仕様事実 20 (第9.22) — EBMode ゲートの原理的な窓
**現象**: `StartWebView2_Full` の実行中〜直後にデバッガでブレーク/ステップ実行すると
Excel がクラッシュ (AV)。**原因**: 全 COM コールバックが通る 91 バイトの EBMode 判定
スタブは「スタブ入場時の EBMode 値」でしか分岐できず、判定通過後にブレーク遷移が競合する
一瞬の窓が構造上残る。**対策は回避 (運用ルール)**: WebView2 のイベントバーストが静定する
まではブレーク/ステップ実行しない。
★D-1 以降はこれに加えて「`EvalSync` の DoEvents ループ中も止めない」が必要★

### 仕様事実 14 と in-callback ガード (D-1)
イベントハンドラ (`View_On*`) の中から `EvalSync` を呼ぶと、ランタイムはハンドラの復帰を
待ち、こちらは JS の完了を待つのでタイムアウトまで固まる。D-1 でガードを入れたので
**今は即座に `LastEvalError = "in-callback"` で戻る**。ハンドラ内で JS の結果が要るときは
SafeTimer で一拍置いてから呼ぶこと (`RequestNewTabAsync` と同じ型)。
★D-2 の `Wv2Element` も全メソッドがこの経路を通る★ (`LastError = "in-callback"`)。

### 仕様事実 30 / 33 (D-1 / D-2) — 結果 JSON のエスケープ
不等号の開き側は `<` にエスケープされて届くが、**閉じ側はそのまま届く**
(D-2 実測: `at <anonymous>`)。`Wv2Json.JsonUnescapeAt` が復号するので
VBA 側では素の文字列が得られるが、シミュレータを書くときは実物に合わせること。

### D-2 の設計の要点 (再確認用)
- **世代は JS が発行する** (`'g' + Date.now() + '-' + Math.random()`)。
  **判定の権威は常に JS 側** (設計原則91)。`Wv2Pane.CurrentDomGen` は
  「安全側にしか外さない高速パス」でしかない
- **JS 側レジストリは注入しない。** 全検索式の先頭に自己生成プロローグを埋め込む
  (設計原則92)。ページ遷移・SPA 書き換え・`about:blank` で自己修復する
- **`Nothing` と空文字の意味は `LastEvalOk` / `LastOk` で区別する** (設計原則93)
